# Domain Docs

This repository uses a single-context layout.

Before exploration, read the root GLOSSARY.md and relevant decisions in
docs/adr/. If GLOSSARY-MAP.md exists, follow its context pointers instead.
Proceed silently when domain documents do not exist.

Use glossary vocabulary in specs, issue titles, and tests.
If a proposal conflicts with an ADR, identify the conflict explicitly.
Create domain documents when terminology or decisions are resolved,
rather than scaffolding empty documents.
